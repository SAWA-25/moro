# 循迹 App Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 根据截图新增独立「循迹」App，只实现截图内“循迹App”相关功能：人格模拟 Screenlife 演出、右下角写回开关、类似 lookus/异地恋 App 的监视功能与报备功能；所有截图列出的功能点都要有可操作、可查看、可配置、可落库的完整 UI/数据流。

**Architecture:** 新增 `AppID.Xunji`、桌面入口、懒加载路由和 IndexedDB 存储；核心数据由 `utils/xunji.ts` 生成/演进，App UI 在 `apps/XunjiApp.tsx` 中按“人格模拟 / 监视 / 报备 / 设置”分区。人格模拟可调用副 API 生成角色一天 Screenlife 记录，并根据“发送给角色”开关写入循迹记录与角色自主生活/备忘录/聊天上下文关联；监视与报备功能采用 local-first 模拟数据，不接真实手机传感器，但 UI 与交互完整模仿市面异地恋定位/手机状态类 App。

**Tech Stack:** React + TypeScript + Vite；IndexedDB via `utils/db.ts`；现有 OSContext/useOS；Phosphor Icons；包管理统一 `pnpm`。

## Proposed Product Design

### Navigation

「循迹」App has four bottom tabs:

1. `演出` — Screenlife 人格模拟
2. `监视` — lookus-like dashboard
3. `报备` — event notification/report feed and rule toggles
4. `设置` — target role, write-back toggle, simulation density, reset/demo refresh

Top area always shows selected role card:

- Avatar / name
- phone model
- current status: online / screen on / sleeping / moving / calling / charging
- last update time
- privacy note: “这是角色人格模拟数据，不读取真实设备”

### Screenlife 演出

User flow:

1. Select character.
2. Pick time range preset: 今天 / 昨天 / 自定义 2h / 自定义一天.
3. Choose performance density: 轻量 / 标准 / 详细.
4. Toggle “发送给角色 / 写回日常” in lower-right floating settings pill.
5. Tap “开始演出”.
6. App creates a Screenlife day composed of:
   - app sessions timeline
   - chats/messages summary
   - browsing/feed records
   - memos/notes
   - lock/unlock/network/battery/location/health/call events
   - narrative recap from role perspective
7. If write-back is enabled:
   - Save generated `XunjiScreenlifeRun` with `writeBack=true`.
   - Also create cross-link records in `xunji_reports` and optionally character memos / `CharLifeEvent`-style summaries through DB helper, so future chat context can reference it via planned `buildXunjiContextBlock`.
8. If disabled:
   - Save run as `ephemeral` or keep only in app history (depending product choice), but do not inject into role context.

### Monitoring UI imitation

Implement realistic panels, not static text only:

- Phone usage card:
  - `screenTimeMinutes`, `unlockCount`, lock periods, app usage timeline, duration ranking bars.
- Network card:
  - current network type WIFI/mobile, SSID/carrier, timeline of switches.
- Device card:
  - phone model, OS-like version, storage/battery summary.
- Location card:
  - distance to user mock value, current place, map-like route visualization, navigation button, stay timeline, historical trajectory.
- Health card:
  - stress, HRV average/current, HRV mini trend SVG/CSS chart, heart rate range/latest/trend, sleep duration/quality/stages, steps/distance/day/week trends.
- Calls card:
  - timeline records with object/duration/status.
- Battery card:
  - percentage, charging status, last charge/discharge events.

### Reporting UI imitation

Implement a feed + rules page:

- “今日报备” feed with event cards:
  - unlock count report
  - network switch report
  - app enter/close report
  - app used for N minutes; hourly reminder event
  - charge started/ended
  - location start moving / stayed / transit / arrived
  - phone call started / every 10 min duration reminder
  - sleep phone-off / after 21:00 no sleep reminder / every 5h sleep duration reminder / sleep ended
- Rule toggles for every report type.
- “生成今日报备” button regenerates deterministic/simulated feed from current monitoring snapshot.
- “写入角色” button, if enabled, marks chosen report items as known to role.

## Risks / Tradeoffs

1. **“完整模仿市面 App” vs real device data**
   - Browser cannot read another person’s real phone usage, health, location, calls, WiFi, etc.
   - Implementation must clearly be “角色人格模拟 / local-first fiction data” while UI imitates market app behavior.

2. **写回角色的 scope**
   - Directly inserting messages into chat would surprise users.
   - Safer MVP writes to Xunji stores + character memos/context block. Later, if user wants, add explicit “发送成聊天卡片”.

3. **Large single file**
   - `apps/XunjiApp.tsx` can grow big. If over ~1000 lines, split into `apps/xunji/` components.

4. **DB version bump**
   - Must ensure stores are created idempotently and no existing store/index migration breaks older users.

5. **LLM JSON fragility**
   - Must keep local fallback complete and parse defensively like `autonomousLife.ts`.
